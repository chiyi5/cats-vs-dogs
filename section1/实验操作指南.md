## 1. 先与包②统一基线

必须统一：实际 train/val 文件列表、类别映射、预训练权重、输入裁剪、增强、优化器、学习率、训练轮数、batch size、冻结策略和验证选模规则。包②的最终调参模型可以不同，但应另列为最终模型，避免把不同设置当成同一个 E1。

本脚本暂定：ResNet18 全量微调；ImageNet V1 权重；SGD momentum=0.9、weight decay=1e-4；初始学习率 0.001、余弦调度；20 轮、batch size=16；短边 resize 后中心裁剪；训练增强为水平翻转和 ±10° 旋转；验证不随机增强；选择验证准确率最高的轮次，同分取较早者。以上是起跑配置，不是最优参数结论。

| 配置 | 唯一主要变化 | 如何解释 |
|---|---|---|
| E1 | 预训练、增强、224 输入 | 共同基线 |
| E2 | 关闭随机增强 | E1−E2：增强影响 |
| E3 | 随机初始化 | E1−E3：该训练预算下预训练影响 |
| E4 | 输入改为128 | E1−E4：分辨率影响 |
| E5 | 灰度128、HOG、训练集拟合StandardScaler、线性SVM | 整体流程对照，不能当单因素消融 |

## 3. 先跑通，再跑正式实验

在终端执行：

```bash
conda activate ee6483
cd /home/devcontainers/6483/cats-vs-dogs
python section1/run_experiment.py --help
python section1/run_experiment.py --data data/dataset --experiment E1 --epochs 1 --output section1/results/smoke
```

单轮只检查流程，不进入正式对比表。脚本读取整个训练集，耗时取决于图片解码和机器状态。显存不足时统一降低所有神经网络实验的 batch size；先用 workers=0，确认后再尝试提高。此脚本未实施数据去重、损坏图像修复或混合精度。

与包②确认配置后运行五组：

```bash
for exp in E1 E2 E3 E4 E5; do
  python section1/run_experiment.py --data data/dataset --experiment "$exp" --seed 42 --output section1/results/formal
done
```

检查每次执行是否成功，失败的运行不会生成最终 metrics.json。脚本拒绝复用已写入config.json的目录；失败重跑应指定新output保留原记录。不要边跑边修改代码。训练中会保存逐轮 history.csv；每次最终保存 metrics.json、验证预测、配置及文件清单，神经模型还保存最佳权重。E5保存模型文件，特征提取可能占用较多内存。

单种子五组可先形成探索结果，时间允许再给 E1–E4 补种子123和2026，报告均值、标准差及配对差值。包②最终模型的三种子结果，只有在配置和文件列表完全一致时才能复用为E1。

E3若明显未收敛，应展示曲线并明确“相同预算下”的结论；可给预训练与从零训练各自相同规模的学习率候选集，并另报调优后的结果，不能只给某一组额外调参而隐去成本。

## 4. 结果怎么写

从 metrics.json 提取验证准确率，用 history.csv 画训练/验证损失与准确率曲线。elapsed_seconds 是本脚本的整体流程耗时：神经实验包括权重获取/建模/训练/验证/保存，SVM包括特征提取/拟合/预测/保存；不能直接当成纯训练时间。需要严格比较开销时应另行分阶段计时，预先缓存权重并固定硬件。

| 实验 | 验证准确率 | 猫召回率 | 狗召回率 | 最佳轮次 | 总流程时间 |
|---|---|---|---|---|---|
| E1–E5 | 待实测 | 待实测 | 待实测 | 待实测 | 待实测 |

若E1准确率为a、E2为b，增强影响为100×(a−b)个百分点；初始化、分辨率同理。比较差值的绝对值，同时说明方向。只在这三组受控因素之间讨论哪个影响最大；E5改变整条流程，应单独讨论。单种子差异可能来自随机性，不写成普遍规律。

## 6. Git 同步

pull=拉取队友更新；push=上传本地提交；Pull Request=请求合并。检查时本地尚无提交、section1未跟踪，origin/main显示gone；这不足以断言远程仓库为空，也可能本地引用过期。

先确认远程状态：

```bash
git status -sb
git fetch origin
git branch -a
git log --oneline --all -5
```

如果远程已有main，先处理本地未跟踪文件与远程同名文件可能冲突的问题，再基于远程建分支；不要强制覆盖或直接执行无关历史合并。如果远程确实为空，可以创建首次提交并推送工作分支：
